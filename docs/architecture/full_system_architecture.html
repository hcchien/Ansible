Tris-Aura Full System Architecture

Repo-audited architecture map for the App, local store, Wallet, Issuer, Relay, Forum Host, Web Frontend, AppView direction, federation adapters, external providers, and current compliance gaps. Status chips intentionally distinguish implemented surfaces from partial MVPs, draft systems, external networks, legacy compatibility, and launch blockers.

Included Flows

  • Local-first app storage and publication intent.
  • Wallet and Issuer credential issuance/presentation boundary.
  • Forum Host durable discovery, signed create-board intents, and scoped web-thread MVP, with broader board/moderation scope marked partial.
  • Web sessions approved by the app without exporting DID keys.
  • Nostr direct publish, ActivityPub relay distribution, and AT/PLC compatibility.

Status Treatment

  • Node chips show implementation state.
  • Dashed edges show partial, draft, legacy, external, or gap routes.
  • Nostr, ActivityPub, AT/PLC, web sessions, messenger, reputation, Web Frontend, and Forum Host are partial MVP slices, not pure plans.
  • AppView server remains draft because there is no Phoenix AppView package in the repo.

Boundary Rules

  • Private content stays in the user-controlled boundary.
  • Raw legal identity and private keys do not flow to Relay, Forum Host, AppView, logs, or federation.
  • External host compliance discovery and display exist; local persistence and ranking/sync/trust-policy use remain explicit current gaps.

Constitution Review

This documentation touches identity, storage, sync, verification, federation, moderation, ranking, community governance, Wallet, Issuer, Relay, Forum Host, and AppView behavior. The engineering constitution applies.

  • Local-first private content remains inside the user-controlled app boundary.
  • Wallet credential presentation requires explicit user consent.
  • Issuer proofing may process provider results only inside the Issuer boundary.
  • Raw legal identity, provider assertions, private keys, biometric material, and private content are not shown flowing to Relay, Forum Host, AppView, public credentials, logs, federation, or external hosts.
  • Web sessions are scoped browser sessions and do not imply browser storage of root DID private keys.
  • Forum Host moderation is host-level governance, not global truth.
  • Current gaps are explicitly labeled: hardware-backed key storage/reduced-trust mode, and external host compliance persistence/policy use.
